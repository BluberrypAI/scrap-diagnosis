# 문진 개선 구현 계획

기준 설계: `docs/algorithm-user-review-2026-11-05.md`. 사용자의 ‘개선 시작’에 따라 기존 규칙 엔진과 SCRAP 화면을 유지하는 권고안을 실행한다. 현재 작업 폴더에서 진행하며 기존 미추적 파일은 보존한다. 별도 커밋·배포·실제 LLM 호출은 수행하지 않는다.

## 목표와 제약

- 후속 분류·금지 조건을 바꿀 미확인 사실을 확인하거나 명시적으로 보류한다.
- S4 모름 반복을 없애고, 기존 답을 고쳐 확인을 재개할 수 있게 한다.
- 앞 답 수정 시 영향받는 답을 판정에서 제외하고 재확인 대상으로 보존한다. 웹과 MCP에 같은 정책을 적용한다.
- 문진을 로컬 SQLite에 저장하고 세션 ID로 복원한다. 기준일과 규칙 버전을 고정·검사한다. 테스트는 임시 DB를 사용한다.
- `SCRAP.html` 원본은 수정하지 않는다. 기존 `survey.js`·`survey.css`의 화면과 클래스 체계를 유지한다.
- 후보 수가 줄지 않는 답의 설명, 질문의 확인 방법, 저장·오류 상태, 사용자 선택 코드와 잠정 상태를 정확히 표현한다.
- 문진 밖의 업체·처리 경로 화면은 아직 데모다. 해당 기능까지 완성했다고 표시하지 않는다.
- 법적 수치·판정 규칙을 새로 만들지 않는다. 매핑을 바꾸는 경우 저장된 원문·표에서 확인한다.

## 작업과 검증

1. [ ] **후속 분류 보호와 모름 처리** — `annex4.py`, `compact.py`, `candidates.py`, `engine.py`.
   - RED: 폐유의 PCB 미확인, PCB 모름·양성, 다른 지정 사유, 세부 코드·그 밖의 확인 모름, 충돌을 검사한다.
   - GREEN: 성립 가능한 추가 지정 규칙이 코드 범위나 금지·제한을 바꿀 때만 관련 조건을 묻는다. UNKNOWN은 확인 안내로 멈춘다. S2가 빌린 S3 질문의 도움말도 전달한다.
2. [ ] **답변 수정과 문진 저장** — 공용 답변 변경 처리, 웹 세션 저장·조회, MCP 변경 처리.
   - RED: 종류·시험값 수정 후 코드 재확인, 동일 답 재전송, 배치로 새 코드를 함께 확인, 잘못된 입력의 원자성, 저장 후 메모리 캐시 초기화·재조회, 되돌리기, 규칙 버전 불일치를 검사한다.
   - GREEN: 의존 사실만 무효화하고 이전 값은 재확인 목록으로 보존한다. SQLite 저장 성공 후 새 상태를 반영한다.
3. [ ] **SCRAP 문진 연결** — 기존 질문/결과/근거/베리 구성 안에서 개선한다.
   - 질문 목적과 자료 확인 도움말, 동일 후보 수 문구, 모름 후 수정, 개별 답 편집, 저장 복원, 실패 복구·중복 제출 방지, 실제 완료 상태와 결과 출처를 반영한다.
   - 기존 디자인 구조를 지키고 브라우저에서 문진·모름·수정·새로고침 복구·결과를 확인한다.
4. [ ] **회귀·보고** — 관련 검사 후 전체 pytest를 실행하고, 개선 전 감사 JSON을 보존한 채 개선 후 감사 결과를 별도 생성한다. 실제 사용자 이해도·독립 법령 검증·실제 LLM 품질은 미검증으로 남긴다.

## 검토할 경계

- ‘지정됨’은 확실해도 코드·재활용이 바뀔 수 있는 미확인 조건.
- 모름과 자료 충돌, 최초 답변과 기존 답의 수정, 배치 입력의 구별.
- 범위가 같은 종류 간 변경, 과거 시험값과 코드의 재사용.
- 저장 실패·같은 답 중복·기준일 및 규칙 버전 변경·서버 재시작.
- 코드 자동 결정과 사용자 선택, 처리 경로 데모와 문진 저장의 구별.
