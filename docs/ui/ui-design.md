# 문진 서비스 UI 설계 (ui-v1)

UI팀에 넘기는 화면 설계다. **화면 흐름·구조·상태 처리의 기준은 이 문서다.** 참조 화면(`web/`)은 이 설계가 실제로 동작하는지와 응답 형식을 확인하는 테스트용이며, scrap-web은 이 코드를 복사하지 않고 직접 구현한다([handover.md](handover.md)). API 형식은 `docs/ui/ui-contract.md`와 `docs/api/api-spec.md`에 있다.

## 1. 서비스 의도를 화면으로
| 의도 | 화면에서 드러나는 방식 |
|---|---|
| 아는 만큼 말하면 덜 묻는다 | 첫 화면이 빈 질문지가 아니라 "아는 만큼 적어 주세요" 입력창이다. 말한 내용이 판정 보드의 '확인된 사실'에 바로 채워지고 출처 배지 '말함'이 붙는다. 기업 정보에서 온 사실은 '기업 정보' 배지가 붙고 묻지 않는다 |
| 질문은 필요한 것만, 한 번에 하나 | 대화 끝에 지금 질문 카드 하나만 있다. 위험 항목은 묶음 카드 한 장으로 묻는다("모두 해당 없음" 한 번) |
| 판정 근거는 투명하게 | 보드에 남은 후보 수, 확정을 막는 항목, 결론 조건 체크리스트가 보인다. 결과 카드는 근거 조문을 펼쳐 볼 수 있고 "검토 전 규칙(참고용)"을 항상 표시한다 |
| 증빙이 필요한 것은 증빙으로 | 시험 수치를 모르면 같은 서류로 확인할 항목을 묶은 서류 요청 카드가 나온다 |
| 확정하면 다음 단계로 | 확정 뒤 같은 화면에서 '다음 단계로 넘기는 내용'(경로추천 AI 인계)을 요약해 보여 준다. 코드가 없는 결론도 확정하고 무엇을 하면 되는지 안내한다 |

## 2. 화면 목록과 흐름
```
#/company  기업 정보 (최초 1회, 이후 수정)
   │
#/cases    건 목록 ──[새 문진]──▶ #/cases/new ──(첫 메모 전송)──▶ #/cases/:id 문진
   ▲                                                              │
   └──────────────(목록으로)───────────────────────────────────────┤
                                                                  ├─ 확정 → 인계 요약(같은 화면)
#/cases/:id/history  판정 기록 ◀──[기록 보기]──────────────────────┘   └─[다시 열기]→ 문진 재개
```
- 기업 정보가 없으면 목록 첫 화면에 "기업 정보를 먼저 입력하면 질문이 줄어듭니다" 안내 카드를 보여 준다(입력을 강제하지는 않는다).
- 로그인은 다른 팀 담당이다. 참조 구현은 개발용 회사 선택(회사 만들기/고르기)으로 `X-Company-Id`를 정한다.

## 3. 화면별 설계

### 3.1 문진 화면 `#/cases/:id` (핵심)
데스크톱(≥1080px): 2열이다. 왼쪽은 대화(유연), 오른쪽은 판정 보드(고정 360px)다.
```
┌ WorkBar: [← 목록]  PP(폴리프로필렌) · 문진 중        질문 2/12   [기록] ┐
├──────────────── 대화 ────────────────────┬────── 판정 보드 ───────────┤
│ 나   PP 사출 스크랩이에요. 고체예요.         │ 결론 상태  확인 중           │
│ AI   기름·잔류물·PCB·유해화학물질 중…       │ ─ 확인된 사실 ─────────────  │
│ ┌ 질문 카드 ─────────────────────────┐   │ 소재   PP          [말함] ✎ │
│ │ 이 폐기물에 해당하는 것이 있나요?   │   │ 상태   고체        [말함] ✎ │
│ │  · 지정폐기물 잔류물  · PCB … (항목) │   │ 배출시설 있음   [기업 정보]  │
│ │ [모두 해당 없음] [해당 있음/모르겠음]│   │ ─ 확인이 필요한 항목 ───────  │
│ │ ▸ 어떻게 확인하나요?                 │   │ ○ 기름·잔류물·PCB·유해화학  │
│ └──────────────────────────────────┘   │ ─ 남은 후보 22개 ──────────  │
│                                          │ 51-03-01 폐합성수지류 …      │
│ [ 자유롭게 입력하거나 위에서 고르세요… ⏎ ]  │ ─ 필요한 서류  없음 ───────  │
└──────────────────────────────────────────┴────────────────────────────┘
```
- **대화:** 사용자 말(오른쪽 정렬)과 AI 말(왼쪽)이 이어진다. 지난 질문 카드는 접힌 요약("모두 해당 없음을 고르셨어요")으로 남긴다. 지금 카드만 조작할 수 있다.
- **입력창:** 항상 보인다. 카드 버튼 대신 말로 답해도 된다(서버가 해석). 전송 중에는 잠그고 "판정 중…" 점 애니메이션을 보여 준다.
- **질문 카드:** `ui.question.input`에 따라 그린다(§4).
- **판정 보드:** `ui.board`를 그대로 그린다.
  - 사실 행의 ✎는 `editable`일 때만 보인다. 누르면 그 자리에서 편집(선택지 또는 숫자 입력)하고, 저장하면 `quick_reply value`를 보낸다. "모름으로 되돌리기"는 `retract`를 보낸다.
  - EVIDENCED 사실은 "서류로 확인" 배지와 문서 링크가 붙고 편집할 수 없다.
- **분기별 카드:**
  - REQUEST_EVIDENCE → 서류 요청 카드
  - RESOLVE_CONFLICT → 충돌 카드
  - FINAL_REVIEW → 결과 카드
  - UNSUPPORTED → 판정 불가 카드
- **좁은 화면(<1080px):** 1열이다. 판정 보드는 상단 요약 막대("확인된 사실 3 · 남은 후보 22 · 서류 0  [보드 열기]")로 접고, 누르면 오른쪽 서랍으로 연다.

### 3.2 새 문진 `#/cases/new`
- 대화 화면과 같은 틀에서 첫 AI 말: "어떤 폐기물인지 아는 만큼 적어 주세요. 소재, 상태, 기름·약품이 묻었는지, 예전 신고 번호 등 무엇이든 좋아요."
- 예시 칩: "PP 사출 불량품이에요", "도금 라인 폐황산", "폐수처리 오니". 누르면 입력창에 채운다.
- 접을 수 있는 "수량·발생 시기" 입력(선택)
- 전송하면 `POST /cases {memo, quantity, unit, period}` → `#/cases/:id`로 바꾸고 첫 턴을 그린다.
- 메모 없이 "질문부터 받을게요"를 누르면 memo 없이 만든다.

### 3.3 결과 카드와 인계 요약 (문진 화면 안)
```
┌ 판정 결과 ─────────────────────────────────── [검토 전 규칙 · 참고용] ┐
│ 51-03-01  폐합성수지류(폐염화비닐수지류는 제외한다)    사업장일반폐기물  │
│ 조건  ✔ 소재 PP  ✔ 고체  ✔ 오염 없음  ✔ 폐기물관리법 적용             │
│ ▸ 근거 보기 (시행령 별표 1 …, 시행규칙 별표 4 51-03-01)                │
│                         [다시 확인할게요]   [확정]                     │
└────────────────────────────────────────────────────────────────────┘
```
- **코드 없는 결론:** 큰 글씨로 코드 대신 결론(`ui.result.conclusion`)을 쓴다. 예: "폐기물관리법상 폐기물이 아닙니다". 버튼은 같다.
- **"다시 확인할게요":** 보드의 사실 편집을 강조하고 입력창에 포커스한다.
- **확정:** 확인 대화상자("확정하면 판정이 기록되고 다음 단계로 넘어갑니다")를 거쳐 `POST /confirm`을 보낸다.
- **확정 후:** 카드가 인계 요약으로 바뀐다.
  - 넘기는 내용: 행동(`route_guidance.action`의 한국어 이름), 요지(`summary`), 참고(`notes`)
  - 확정 시각(대화 시작 시각, 법 기준일)
  - 버튼: [경로 추천으로] (참조 구현은 인계 JSON을 보여 주는 모달), [기록 보기], [목록으로]
  - 입력창은 잠그고 "확정된 건입니다. 고치려면 기록에서 다시 여세요"를 보여 준다.

### 3.4 건 목록 `#/cases`
- 머리: "내 폐기물" + [새 문진]
- 상태 탭: 전체 / 문진 중 / 추가 정보 필요 / 확정 (+ 운반 중·완료는 '이력'으로)
- 카드: `summary.title`, 결과(`result_label` 또는 "미정"), 상태 배지(`status_label`), 다음 할 일(`next_action`), 갱신 시각. 누르면 문진 화면(확정 건은 결과·인계 요약이 펼쳐진 상태)으로 간다.
- 빈 상태: "아직 문진한 폐기물이 없어요" + [새 문진]

### 3.5 기업 정보 `#/company`
- 3단계: ① 기본 정보(회사명·업종·주소) ② 배출시설(복수 선택 칩 + "해당 없음") ③ 주생산품(태그 입력)
- 단계 표시는 scrap-web `.onboarding-progress` 형태다. 저장하면 `PUT /companies/me/profile`.
- 저장 후 안내: "배출시설 정보는 문진에서 다시 묻지 않습니다"(서버가 계산한 `facts` 표시)

### 3.6 판정 기록 `#/cases/:id/history`
- 판정 버전 목록: 버전, 결과, 확정 시각, 대체 여부(다시 열기 시각·사유)
- 타임라인(`GET /trace`): 턴마다 사용자 입력, 들어간 사실, 고른 분기와 이유, 질문 선택 근거(접기)
- [다시 열기]: 확정 건만 보인다. 사유를 입력받아 `POST /reopen`을 보내고 문진 화면으로 간다.

## 4. 질문 카드 유형 (`ui.question.input`)
| input | 그리는 법 | 보내는 값 |
|---|---|---|
| `choice` | 선택지 버튼 세로 목록(라벨). 마지막에 "모름"(`allow_unknown`) | `quick_reply {key, kind:"value", value}` / `{kind:"unknown"}` |
| `group` | 제목 + 항목 목록(`items`). `answered_items`가 있으면 "○○은 확인했어요"를 먼저 쓴다. 버튼 두 개 | `{key: group_id, kind:"none_all"}` / `{kind:"expand"}` |
| `material_group` | 분류 타일 격자(13개, 아이콘 없이 라벨) + "잘 모르겠어요" | value = 분류 값 |
| `material` | 검색창 + 목록(분류 안 소재, 최대 14개). 목록 밖은 "목록에 없어요"(=모름) | value = 소재 값 |
| `number` | 구간 버튼(options, 예 "5% 미만")과 "정확한 값 입력"(숫자 + 단위). "모름" | 구간: value = NumRange dict / 직접: value = 숫자 |
| `code` | 별표 4 번호 목록(번호 굵게 + 명칭). '그 밖의'로 시작하면 "다른 번호에 해당하지 않을 때만" 안내 | value = 번호 |

공통 규칙
- 카드 제목은 `question.text`다. 응답 `message`는 대화 말풍선에 쓴다.
- `help`는 "어떻게 확인하나요?"로 접어 둔다.
- 버튼을 누르면 사용자 말풍선에 그 라벨을 남긴다.
- 키보드: 선택지는 화살표로 이동하고 Enter로 고른다. 새 카드가 나오면 카드 제목으로 포커스를 옮긴다.

분기 카드
- **서류 요청(REQUEST_EVIDENCE):** 필요한 서류마다 행을 둔다(`ui.requested_documents`: 서류 이름, 확인 항목).
  - 끌어다 놓기·파일 선택(.pdf/.txt/.md)을 지원한다. LLM이 꺼진 환경을 위해 "값 직접 입력"을 둔다(항목별 숫자 → `facts` 필드).
  - [서류가 없어요]를 누르면 서버로 `text: "서류가 없어요"`를 보낸다.
- **충돌(RESOLVE_CONFLICT):** `ui.conflicts`의 `choices` 버튼이다. `action: UPLOAD`이면 서류 요청 카드를, `EDIT_FACT`이면 보드 편집을 연다.
- **판정 불가(UNSUPPORTED):** 사유 문장(message), 확인할 항목(`board.pending`), [목록으로]. 상태 배지는 "추가 정보 필요"다.

## 5. 상태와 예외
| 상황 | 화면 |
|---|---|
| 전송 중 | 입력창·카드 잠금, 말풍선 자리 "판정 중…" |
| 409 동시 수정 | "다른 창에서 이 건이 바뀌었어요. 새로 불러옵니다" → `GET /cases/{id}` |
| 409 확정 불가 | 서버 메시지를 그대로 보여 주고 최신 턴을 다시 그린다 |
| 401 회사 없음 | 개발용 회사 선택 화면으로 |
| 네트워크 오류 | 말풍선 자리 "보내지 못했어요 [다시 보내기]"(입력 내용 유지) |
| 확정된 건 | 입력·편집 잠금, 인계 요약 표시 |

## 6. 문구 원칙
- 존댓말, 짧게. 법률 용어는 처음 나올 때 쉬운 말을 붙인다(예: "지정폐기물(유해성이 있어 따로 관리하는 폐기물)").
- 판정은 "~로 판정됩니다"(규칙이 정함)로 쓰고, AI가 정한 것처럼 쓰지 않는다.
- 모든 결과에 "검토 전 규칙에 따른 참고 판정"을 표시한다(`review: UNVERIFIED`).

## 7. 접근성·반응형
- 대화 영역 `aria-live="polite"`, 오류 `role="alert"`, 새 카드가 나오면 제목으로 포커스한다.
- 색만으로 상태를 구분하지 않는다(배지에 글자). 포커스 링을 지우지 않는다.
- 너비 기준: ≥1080 2열, 720–1079 1열 + 보드 서랍, <720 모바일(카드 버튼 전체 폭, 보드 하단 시트)

## 8. 참조 화면의 테마 토큰 (`web/src/theme/tokens.css`, 변수 이름은 scrap-web `global.css`와 같음)
scrap-web `global.css`의 변수 이름을 그대로 쓴다. 참조 구현은 scrap-web의 값으로 시작한다.
| 토큰 | 쓰는 곳 |
|---|---|
| `--color-primary`, `--color-primary-deep`, `--color-on-primary` | 주 버튼, 선택된 칩, 진행 막대 |
| `--color-secondary`, `--color-surface-lavender` | 보드 배경, AI 말풍선 |
| `--color-accent-lime` | 확정·완료 강조 |
| `--color-background`, `--color-card` | 화면 배경, 카드 |
| `--color-text-primary`, `--color-text-secondary`, `--color-muted` | 글자 |
| `--color-border`, `--color-border-light` | 테두리·구분선 |
| `--font-sans` | 글꼴 |
| `--spacing`, `--app-content-width` | 간격 단위, 본문 폭 |

scrap-web에 없어서 추가하는 토큰(이름 접두어 `--wd-`): `--wd-radius`, `--wd-shadow`, `--wd-board-width`, `--wd-status-diagnosing`, `--wd-status-needs-info`, `--wd-status-confirmed`, `--wd-warn`, `--wd-danger`, `--wd-success`. 컴포넌트 CSS에는 색을 직접 쓰지 않는다.
