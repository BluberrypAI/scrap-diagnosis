# 이미지 인식 → 문진 대응표 (초안)

AI허브 「산업 폐기물 이미지」 데이터셋의 클래스가 문진 엔진의 어느 질문·소재·분류번호 후보와 이어지는지 정리한 표다.
이미지 인식 기능을 만들지 말지, 만든다면 어디까지 쓸지를 정하기 위한 자료이며 아직 구현 계약이 아니다.

- 작성: 2026-11-11
- 상태: 초안. 데이터셋 클래스 일부는 제3자 자료로만 확인함(아래 "확인 수준")
- 엔진 쪽 기준: `knowledge/materials.yaml`(소재 98개), `knowledge/facts.yaml`, `knowledge/annex4_codes.yaml`

## 0. 왜 사진이 필요한가

사진은 인식 기능이 없더라도 받아야 한다. 경로추천 이후 처리업체에 연결할 때 업체가 폐기물 상태를 보고 견적과 수거 가능 여부를 판단하기 때문이다. 그래서 순서는 다음과 같다.

1. **사진 받기·보관·인계(필수)**: 문진 중에 사진을 받아 저장하고, 확정 인계 객체(`docs/handoff-contract.md`)에 사진 참조를 실어 경로추천·업체 연결로 넘긴다. 지금 인계 계약에는 사진 필드가 없다.
2. **이미지 인식(부가)**: 같은 사진으로 소재 후보를 제안한다. 아래 표의 범위로 한정한다.

> **2026-11-11 판단: 이미지 인식은 우선순위를 낮춘다.** 사진만으로 하나로 좁힐 수 있는 소재는 98개 중 약 15개이고, 대부분 원래 문진이 짧은 일반·재활용 고체다. 지정폐기물 후보(액체·오니·광재·분진 등)는 겉모습으로 가를 수 없다. 그쪽은 대상 인식보다 **용기 라벨·MSDS·기기 명판을 글자로 읽는 방식(OCR)**이 쓸모가 크므로, 다시 다룬다면 서류 읽기 계약(`docs/document-extraction-contract.md`)의 연장으로 검토한다.

## 1. 원칙

1. **이미지는 사실을 정하지 않는다.** 이미지 결과는 "제안"일 뿐이고 사용자가 확인해야 `CLAIMED`가 된다. 이미지만으로 `EVIDENCED`가 되는 일은 없다.
2. **이미지는 소재 `presets`를 채우지 않는다.** presets는 사용자가 소재를 고른 뒤에 적용된다.
3. **지정폐기물 판단(S3)에는 쓰지 않는다.** 시험 수치(`cost: TEST`)와 서류(`cost: DOCUMENT`)가 필요한 사실은 사진으로 대신할 수 없다.
4. 이미지가 하는 일은 두 가지뿐이다.
   - **소재 질문(`material`)의 선택지 순서를 바꾸고 후보를 미리 표시한다.**
   - **확인이 필요한 질문을 앞당긴다.** 예를 들어 페인트통이면 잔류물 질문을 먼저 묻는다.

## 5. 데이터셋이 다루지 않는 소재 그룹

아래 소재 그룹은 데이터셋에 해당 클래스가 없다. 사진을 올려도 인식 결과가 "해당 없음"이어야 하고, 엉뚱한 클래스로 강제로 분류되면 안 된다. 따라서 **"모름 / 학습 범위 밖" 출력이 꼭 있어야 한다.**

| 소재 그룹 | 예 | 지정폐기물 후보 여부 |
|---|---|---|
| sludge 오니 | 폐수처리·공정 오니 | 있음 (01-02) |
| slag 광재 | 제강·비철 광재 | 있음 (03-01) |
| dust_ash 분진·소각재 | 집진 분진, 비산재 | 있음 (03-02, 03-05) |
| sand 주물사·폐사·내화물 | 폐주물사, 샌드블라스트 폐사 | 있음 (03-03, 03-04) |
| oil 기름 | 폐윤활유, 절삭유 | 지정만 (06-01) |
| acid_alkali 산·알칼리 | 폐염산, 폐가성소다 | 지정만 (02) |
| solvent_paint 용제·페인트 | 시너, 페인트 | 지정만 (04, 05) |
| catalyst_adsorbent 촉매·흡착제 | 폐촉매, 폐활성탄 | 있음 (03-07, 03-08) |
| product 중 타이어 외 | 전선, 전기전자제품, 태양광 패널, 전지 | 일부 |

**핵심 한계:** 지정폐기물이 될 수 있는 소재는 거의 모두 이 표에 있다. 반면 데이터셋은 일반폐기물이나 재활용 계열의 고체에 치우쳐 있다. 이미지 인식이 가장 잘 맞히는 영역은 원래 문진도 짧은 영역이다.

## 6. 정해야 할 것

1. **건설 계열 소재를 카탈로그에 넣을지.** 폐콘크리트, 폐벽돌, 폐보드류, 폐도자기조각은 별표 4에 번호가 있지만 `materials.yaml`에는 없다. 데이터셋 10종 중 4종이 여기에 해당한다. 넣는다면 「건설폐기물의 재활용촉진에 관한 법률」 적용 범위를 따로 검토해야 한다(엔진에는 아직 이 법의 규칙이 없다).
2. **사진만 본 인식 결과를 어떻게 기록할지.** 제안은 사실 표에 넣지 않고 별도 기록(예: `image_suggestion`)으로 남긴다. 사용자가 확인하면 `source_type`에 이미지 출처를 남긴 `CLAIMED`로 저장한다. 이 방식은 `docs/handoff-contract.md`와 추적 기록(`trace`)에 영향을 준다.
3. **멀티모달 LLM으로 먼저 시험할지, 데이터셋으로 모델을 학습할지.** 위 표대로라면 데이터셋으로 학습해 얻는 이득은 "소재 그룹 1개 고르기"와 "용기면 잔류물 질문 앞당기기" 정도다. 먼저 LLM에 학습 없이(zero-shot) 분류시키고, 데이터셋 일부를 평가셋으로 써서 정확도를 재는 쪽을 권한다. 외부로 사진을 보낼 때는 `docs/llm-data-policy.md`를 따른다.

## 7. 아직 확인하지 못한 것

- 소분류 72종의 전체 목록과 정확한 이름 (데이터 명세서가 필요하며, 내려받으려면 승인이 필요)
- 대분류 개수가 자료마다 다름: AI허브 페이지는 10종, 제3자 자료는 6개 대분류라고 한다
- 재질(Material) 속성값 목록
- 이용 약관 원문: 상업적 이용, 2차 저작물(학습 모델) 배포, 해외 클라우드에서 학습해도 되는지
- 생활 폐기물 짝 데이터셋이 있는지 (페이지에 생활 폐기물 모델 지표가 있음)
