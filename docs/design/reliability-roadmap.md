# 장기 운영 신뢰성 로드맵 (향후 할 일)

> 상태: **제안, 결정 대기** (2026-11-12). 이번 작업에서는 구현하지 않고 할 일로 남긴다.
> 관련: [rule-review-and-amendment.md](rule-review-and-amendment.md)(전문가 검토·법령 개정 반영 설계)

## 0. 왜 필요한가

오래 운영할 때 "판정을 믿을 수 있는가", "고쳐도 안 깨지는가"를 보장하기 어렵다. 2026-11-12 개발 중에 나온 문제는 모두 사람이 화면을 직접 눌러 보고서야 찾았다.

| 문제 | 미리 잡을 수 있었던 방법 |
|---|---|
| 질문 상한 12회에 걸려 판정 전에 멈춤 | 모든 경로를 끝까지 자동으로 돌려 보기 |
| 서류 값 직접 입력이 실제 서버에서 늘 실패(웹 테스트는 가짜 API만 사용) | 화면을 실제 API에 붙인 테스트 |
| 오니에 맞지 않는 유해화학물질 질문 → MSDS 요구로 막힘 | 막다른 길 자동 탐지 |
| 같은 안내만 반복하고 푸는 방법을 말하지 않음 | "모든 멈춤에는 할 일 안내가 있다" 자동 검사 |
| 규칙 하나를 고치면 진행 중인 모든 문진이 `KB_CHANGED`로 멈춤 | 테이블 단위 버전(아래 3.4) |

지금 검증은 단위 테스트, 골든 시나리오, **기존 엔진 판정표**(정답이 아니라 기존 엔진의 답) 비교다. 규칙은 모두 전문가 검토 전(`UNVERIFIED`)이다. 즉 "코드가 의도대로 돈다"까지만 확인되고, "판정이 맞다"와 "사용자가 막히지 않는다"는 확인되지 않는다.

## 1. 진단: 설계의 뼈대와 이음매

**유지할 뼈대**
- AI는 말을 사실로 바꾸기만 하고 판정은 규칙 엔진이 한다.
- 규칙 원본은 `knowledge/` 한 곳에 두고 빌드한다.
- 참·거짓·모름 평가와 조문 근거 추적.

**고칠 이음매**
1. **소재 중심 구조**: 법 규칙을 소재마다 접어 테이블 101개를 만든다. 법은 폐기물 종류와 성질(pH·용출·기름 등)로 판정하므로, 목록에 없는 폐기물은 빈틈이 되고(대체 경로에 지정 기준이 빠짐) 공통 질문이 맞지 않는 폐기물에도 붙는다.
2. **기존 엔진을 정답으로 삼음**: 기존 엔진의 가정과 오류가 "기존과 같다"로 통과한다.
3. **검증이 코드 단위에 치우침**: 사용자 경로 전체와 실제 서버 연결을 보는 검사가 없다.
4. **불확실할 때의 원칙이 없음**: 경로마다 끝나는 방식이 다르다.

## 2. 신뢰성의 네 가지 정의 (결정 대기 Q1)

| | 뜻 | 확인 수단 |
|---|---|---|
| 가. 판정이 맞다 | 법적 정확성 | 공식 질의회신·지침 사례 정답표, 전문가 검토 |
| 나. 막히지 않는다 | 모든 경로가 결론이나 할 일 안내로 끝남 | 경로 자동 탐색(3.2), 증명 검사(4.1) |
| 다. 고쳐도 안 깨진다 | 변경 영향이 보이고 의도하지 않은 변화가 걸러짐 | 차이 보고서, 테이블 단위 버전, 정답표 CI |
| 라. 운영 중 문제를 안다 | 막힌 건·판정 불가 비율을 기록하고 봄 | 운영 지표, 그림자 판정(4.2) |

제안: (나)·(다)를 먼저, (가)는 전문가와 함께, (라)는 배포 전에.

## 3. 할 일 (기본)

### 3.1 약속 범위와 안전 원칙 (결정 대기 Q2·Q3)
- 서비스는 "정확한 판정 보장"이 아니라 **"근거를 보여 주는 참고 판정 + 불확실하면 확인 경로 안내"**를 약속한다. "검토 전 규칙 · 참고용" 표시는 검토가 끝난 규칙에서만 뗀다.
- **모르면 안전한 쪽**: 확신할 수 없으면 "지정폐기물일 수 있음 + 확인 방법"으로 끝낸다. 증거 없이 일반으로 확정되는 경로가 생기면 테스트가 실패하게 한다.

### 3.2 경로 자동 탐색을 CI에 (결정 대기 Q4)
모든 소재 × 대표 답 유형(없음/있음/모름/서류 없음)으로 문진을 끝까지 돌린다. 다음이 나오면 실패.
- 판정 전에 멈춤, 같은 질문·안내 반복, 할 일 안내 없는 판정 불가, 질문 상한 도달
첫 실행 결과를 현황 지표로 남긴다(이후 개선 효과 비교 기준).

### 3.3 화면 + 실제 서버 테스트 (결정 대기 Q5)
Playwright 등으로 핵심 흐름 4~5개(정상 판정, 성적서 업로드, 값 직접 입력, 서류 없음, 판정 불가 뒤 이어 가기)를 실제 API에 붙여 CI에서 돌린다.

### 3.4 개정 반영 흐름 (결정 대기 Q5, 기존 설계 P4·P5)
- 테이블 단위 버전(P5): 상관없는 테이블의 진행 중인 문진은 멈추지 않는다. 먼저 한다.
- 시행일별 판(`effective_from`/`effective_to`), 개정 조문 영향 보고서, 빌드 차이 보고서(P4).

### 3.5 판정 축을 성질 중심으로 (결정 대기 Q7의 ③)
- 소재는 "질문을 줄이는 지름길"로만 두고, 판정은 폐기물 종류·성질 기준 규칙으로 한다.
- 목록에 없는 폐기물에도 성질 기준 지정 규칙을 모두 적용하고 결과는 "참고·전문가 확인"으로 둔다.
- 목록에 없는 폐기물로 들어온 건은 **미등록 폐기물 목록**에 모아 전문가가 새 소재로 등록한다(AI가 가까운 소재로 판정하지 않는다).
- 공통 질문(유해화학물질·PCB·잔류물 등)에 "어떤 폐기물에 묻는지" 적용 범위를 `knowledge/`에 데이터로 둔다.

### 3.6 정답 기준 교체 (결정 대기 Q6)
기존 엔진 판정표 대신 공식 질의회신·지침 사례로 정답표를 만들고, 전문가가 생기면 검토를 더한다. **전문가가 팀 안팎에 있는지 확인 필요.**

### 3.7 규칙을 고치는 사람 (결정 대기 Q6)
처음에는 전문가가 변경 요청 양식으로 주고 개발자가 `knowledge/`에 반영한다. 편집 화면은 흐름이 안정된 뒤 정한다.

## 4. 할 일 (추가 개선 방안, 결정 대기 Q8)

### 4.1 규칙을 증명으로 검사 (가장 먼저 추천)
규칙은 유한한 조건식이라 SMT 솔버(예: Z3)로 **가능한 모든 사실 조합**을 따질 수 있다. 테스트(고른 사례)가 아니라 증명(전부)이다.
- 빈틈 없음: 어떤 답 조합에서도 결론이나 할 일 안내가 나온다
- 충돌 없음: 같은 조건에서 서로 다른 번호가 나오지 않는다
- 안전 원칙: 지정 기준이 증거로 부정되지 않았는데 일반으로 확정되는 경로가 없다
- 개정 영향: 개정 전후 규칙에서 판정이 달라지는 조합 전체를 뽑는다
필요한 것: 규칙 조건식 → 솔버 수식 변환기. 첫 결과물로 "증거 없이 일반으로 끝나는 조합이 있는가"를 지금 규칙에 돌려 현황을 본다.

### 4.2 그림자 판정으로 상시 감사 (운영 시작 시)
실제 판정은 규칙 엔진이 하고, 뒤에서 법령 원문을 읽은 AI가 따로 판정한다(사용자에게 보이지 않음). 둘이 다를 때만 전문가 검토 목록에 올린다. 규칙 오류와 새 폐기물 유형이 운영 중에 드러난다.

### 4.3 법령 개정 감시 → 변경 초안 자동 작성 (개정이 잦아지면)
국가법령정보센터 공개 API로 관련 법령 개정을 주기적으로 확인 → 바뀐 조문 추출 → AI가 규칙 변경 초안과 영향 보고서(4.1로 달라지는 판정 조합 포함) 작성 → 사람이 승인.

## 5. 제안 순서 (결정 대기 Q7)

재작성하지 않고 이음매를 고친다.
1. 경로 자동 탐색(3.2)과 증명 검사(4.1)로 현황 측정
2. "모르면 안전한 쪽" 원칙(3.1)
3. 테이블 단위 버전(3.4 P5)
4. 판정 축을 성질 중심으로(3.5)
5. 정답 기준 교체(3.6)
6. 운영 시작 시 그림자 판정(4.2), 개정이 잦아지면 개정 감시(4.3)
