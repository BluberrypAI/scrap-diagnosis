# 소재 2단계 질문 결과 보고

측정일 2026-11-08. 모델: Azure AI Foundry 배포(M3와 같음, 추론 모델이라 temperature 기본값).

## 문제
소재별 PRIORITY 테이블이 97개라 소재를 모르면 첫 질문이 '소재' 하나에 선택지 97개였다.
또 "폐유기용제", "폐알칼리"처럼 큰 분류만 말한 진술은 살릴 곳이 없어 LLM이 비워 두었다
(M3 추출 평가에서 놓친 41개 대부분).

## 설계
규칙은 그대로 소재(material)만 참조한다. 소재 분류는 질문을 나누는 데만 쓴다.

- 카탈로그(`FactDef.parent`, `value_parent`): 세부 사실이 상위 분류 사실과 '값 → 분류 값' 대응을 가진다.
  로더가 검증한다. 둘 다 enum, 한 단계만, 자기 자신 금지, `domain`과 함께 쓰지 않음,
  모든 세부 값이 분류 하나에 대응, 대응 값은 상위 분류의 값 영역 안.
- 선택기(`app/rules/selector.py`)
  - 상위 분류를 모르면 세부 사실 대신 상위 분류를 묻는다. 선택지는 세부 값이 남은 분류만.
    점수는 세부 값 가정의 결과를 분류별로 합쳐 계산한다(분류 확률 = 세부 값 확률의 합,
    남는 후보 = 합집합). 기존 점수식·동점 규칙·결정성은 그대로다.
  - 분류가 하나뿐이면 묻지 않고 세부 사실을 바로 묻는다.
  - 분류를 알면 세부 선택지를 그 분류의 값으로 줄인다(맞는 값이 없으면 줄이지 않음).
  - 분류를 '모름'이라 답하면 세부 사실을 전체 선택지로 묻는다.
  - 세부 값을 직접 말하면 분류와 달라도 세부 값이 이긴다(막히지 않음).
- 자동 채움(`router.auto_fill` → `selector.implied_child`): 분류에 세부 값이 하나뿐이면 그 값을
  DERIVED(`parent_single`)로 채운다. 예: '여러 소재가 섞여 나누기 어려운 것' → `mixed_inseparable`.
- 변환기: 기존 `materials.yaml`의 `groups` 13개로 `material_group`을 만들고, `material`에
  `parent`/`value_parent`를 붙인다. 질문 문구·라벨 보정·큰 분류 별칭은 `tools/legacy_overrides.yaml`.
  세부 소재 하나를 가리키는 말(폐윤활유, 폐활성탄 등)은 분류 별칭에 넣지 않았다.
  `special`은 '목록에 없는 소재(unlisted)'를 변환하지 않았으므로 '여러 소재가 섞여 나누기 어려운 것'으로 라벨을 바꿨다.
- 추출기: 큰 분류만 말하면 `material_group`만 채우고 `material`은 비운다. 세부 값을 분명히 말하면 둘 다 채울 수 있다.
  사실 목록 보기에 `parent`/`detail_facts`를 붙였다. guard는 일반 enum 사실로 그대로 검증한다.
  묶음 질문 규칙도 다듬었다. "…해당하지 않나요?"처럼 '그렇다'가 '모두 해당 없음'인 질문에 "네", "그렇다",
  "맞아요"로 짧게 답하면 none_all로 본다(아래 실측에서 범위 묶음 질문 실패가 이것 때문이었다).

분류별 소재 수: 플라스틱·고무 14, 금속 4, 광재 6, 분진·소각재 8, 주물사·폐사·내화물 5, 오니 11, 기름 7,
산·알칼리 11, 용제·페인트 5, 목재·종이·섬유·유리 9, 촉매·흡착제 6, 제품·복합물 10, 섞인 것 1(자동).
한 질문의 선택지는 최대 14개다(이전 97개).

## 골든 평가 (data/golden/real.yaml, 10건)
신규: GR-007("폐유기용제가 나와요" → 다음 질문이 소재, 용제·페인트 5개), GR-008(정보 없이 시작 → 분류 → 소재),
GR-009(섞여서 분리가 안 됨 → 소재 자동). GR-002/003 모의 추출에 `material_group`을 함께 넣었다.

| 실행 | 사례 | 분기 | 질문 대상 | 최종 코드 | 보류 | guard 거부율 |
|---|---|---|---|---|---|---|
| `--mock-extractor`(전체 16건) | 16/16 | 40/40 | 22/22 | 7/7 | 7/7 | 0 |
| 실제 1차(최종 프롬프트) | 10/10 | 25/25 | 15/15 | 3/3 | 4/4 | 0 |
| 실제 2차(최종 프롬프트) | 10/10 | 25/25 | 15/15 | 3/3 | 4/4 | 0 |

두 번 모두 실패한 사례: 없음. 응답 문장 템플릿 대체 0회.

다듬기 전 기록(참고): 처음 문구로 9/10, 분류 규칙을 늘린 뒤 7/10이었다. 실패는 모두 범위 묶음 질문
("네, 그렇습니다", "네 버리는 거고 해당 없어요")을 묶음 답 대신 개별 사실 2개로 뽑아 순환자원 인정 여부가
남은 경우였다(소재와 무관, 처음 문구에서도 한 번 나옴). 묶음 질문 규칙을 다듬은 뒤 위 결과가 나왔다.

## 추출기 평가 (기존 질의회신 60건, `scripts/eval_extractor.py`)
| | M3(이전) | 이후 |
|---|---|---|
| 값 일치(비교 가능 59) | 18/59 | 19/59 |
| waste_kind: 소재로 맞힘 | 11/48 | 10/48 |
| 소재를 못 뽑은 waste_kind 라벨 | 37 | 38 |
| └ 그중 소재 분류로 맞힘(분류가 있는 종류 35) | 해당 없음(0) | 12/35, 틀린 분류 0 |
| └ 분류가 하나인 종류만 | - | 11/17 |
| waste_kind: 소재 또는 분류로 맞힘 | 11/48 | 22/48 |

- 이전에 놓친 큰 분류 진술(폐유기용제, 폐알칼리, 폐유, 분진, 오니, 폐촉매, 슬래그, 폐축전지 등)이 이제 분류로 들어가
  분류 질문을 건너뛴다. 틀린 분류는 0이다.
- 분류가 비어 있는 23건 중 17건은 waste_kind 'other'(음식물, 준설토, 패각, 가축 사체 등)로 변환한 분류에 없는
  폐기물이다. 비워 두는 것이 맞다.
- LLM 결과는 실행마다 조금씩 다르다. 묶음 질문 규칙을 다듬기 전(이 평가에는 직전 질문이 없어 영향이 없는 부분)
  실행은 값 일치 19/59, 소재 또는 분류 25/48(분류로 맞힘 13/33)이었다. 처음 문구는 17/59, 22/48(13/36).
- M3 보고의 "놓친 41개"(59개 중) 기준으로는, 이번 실행에서 놓친 waste_kind 38개 중 12개가 분류로 살아났다.

## 남은 일
- 분류만 알 때도 판정 결과의 후보 목록은 97개 테이블 전체 후보(135개)다. 분류는 규칙이 참조하지 않기 때문이다.
  화면에 후보를 보여 준다면 분류로 거르는 편이 낫다.
- 소재와 분류가 서로 맞지 않을 때 소재를 따르지만 메모를 남기지 않는다.
- 추출 프롬프트 버전(`app/config.py`)은 이번 범위 밖이라 올리지 않았다.
