# M3 결과 보고: LLM 추출·응답·guard

측정일 2026-11-08. 모델: Azure AI Foundry 배포 `gpt-6-luna-2`(추론 모델이라 temperature 지정 불가 → 기본값).

## 구성
- `app/agent/llm_client.py`: `LLMClient` 프로토콜, Azure(Foundry v1·기존 Azure OpenAI 엔드포인트 모두), `FakeLLMClient`
- `app/agent/extractor.py`: JSON Schema(strict) 구조화 추출. 판정 금지·명시된 사실만·허용 값만·근거 구절 원문 복사
- `app/agent/guard.py`: 추출 검증(카탈로그 키, 값 영역, quote 원문 대조, 지어낸 숫자 차단, '모름'은 직전 질문에만, 내부 사실은 제시한 선택지만) / 응답 검증(payload 밖 번호·숫자 금지, 질문 1개, 근거 id)
- `app/agent/responder.py`, `templates.py`: 분기별 payload → LLM 문장. 검증 2회 실패나 LLM 없음 → 결정적 템플릿. 버튼은 코드가 만든다.
- `app/agent/orchestrator.py`: md 10절 한 턴(메시지 → 추출/버튼 → 엔진 → 응답 → Trace), `app/domain/verdict.py`(응답 스키마), `trace.py`
- `data/golden/{sample,real}.yaml` 13건, `scripts/eval.py`, `scripts/eval_extractor.py`

실패·조정 기록
- GR-006 첫 버전: "유해화학물질이 **묻어** 있어요"를 LLM이 '용기 잔류물(designated_residue)'로 해석했다. 카탈로그 문구상 맞는 해석이라 골든 문장을 "MSDS에 유해화학물질로 표시된 물질을 버린다"로 고쳤다.
- GR-001: 묶음 질문에 "기름이나 약품 묻은 건 없어요"라고만 하면 LLM은 PCB를 '없음'으로 보지 않는다. 의도한 보수적 동작이다. 이 경우를 GR-001B로 분리하고, 남은 항목만 짚어 다시 묻도록 응답을 고쳤다. LLM이 '약품'을 어느 사실로 볼지에 따라 묶음 재질문/개별 질문이 갈려, 기대값은 '확정하지 않고 계속 묻는다'로 둔다.
- GR-002 첫 실행: 진술 pH '1 정도'와 성적서 0.8을 충돌로 처리했다. 결론(pH 2.0 이하)이 같은 차이는 충돌이 아니도록 바꿨다(`conflicts._matters`).

## 추출기 평가 (기존 질의회신 60건, `scripts/eval_extractor.py`)
- 라벨 64개 중 비교 가능 59개. 값 일치 18/59.
- **뽑은 값은 18개 모두 맞았다(틀린 값 0).** 놓친 41개는 모두 '뽑지 않음'이다.
- 놓친 것 대부분은 "폐유기용제", "폐알칼리", "2차 폐축전지"처럼 큰 분류만 말한 질의다. 새 카탈로그의 소재는 97개 세부 소재라, LLM이 하나를 지어내지 않고 비워 둔다(보수적 동작). 이 경우 엔진이 소재 질문을 한다.
- guard 거부 1건(같은 사실 중복), 재시도 1건, LLM 오류 0, 평균 3.3초/건.
