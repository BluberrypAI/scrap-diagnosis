# 계획: 소재 우선 문진 + 신뢰할 수 있는 데이터 소스로서의 엔진

작성 2026-11-05 (같은 날 1차안을 소재 우선 방식으로 고쳐 씀). 코드는 아직 바꾸지 않았다.

## 1. 목표와 범위

- **사용자 경험**: 사용자는 질문에만 답한다. 첫 질문은 "무슨 소재인가요"(PP·고철·슬래그…)이고, 이후에는 그 소재의 법적 지위를 정하는 데 필요한 질문만 받는다. 법령 명칭 목록에서 번호를 고르는 일은 없다.
- **엔진의 역할**: 결과를 이후 단계(시설 추천·수거·처리 지원)가 믿고 쓸 수 있는 **판정 기록**으로 낸다.
- **이번 범위가 아닌 것**: 외부 기업·시스템 연동, 구체적인 처리 절차 안내.
- **SCRAP 디자인과의 관계**: 디자인 문진(주된 물질 → 고체상태 → 형태 → 51-03-01)이 이 방식의 원형이다. 디자인의 질문 흐름을 뼈대로 쓰고, 디자인이 건너뛴 법적 확인(폐기물 여부·다른 법 적용·오염)만 엔진이 끼워 넣는다.

## 2. 설계 원칙

1. **법 판단은 공통 규칙 엔진 한 곳에만 둔다.** "기름 5% 이상이면 폐유", "지정폐기물이 남아 있으면 그 지정폐기물"처럼 모든 소재에 똑같이 적용되는 기준을 소재마다 복사하지 않는다(법 개정 시 한 곳만 고침).
2. **소재 카탈로그는 앞단의 데이터다.** 소재 → (기존 폐기물 종류, 번호 후보, 미리 정해지는 사실, 같은 소재 안에서 번호를 가르는 질문). 법 판단을 담지 않는다.
3. **소재별 판정표는 엔진으로 자동 생성한다.** 소재마다 필요한 질문의 모든 답 조합을 엔진에 돌려 "답 → 분류번호·지정 여부" 표를 만든다. 이 표가 테스트 기준이자 법률 검토 자료가 된다.
4. **LLM은 소재를 제안만 한다.** 목록에 없는 설명은 LLM이 카탈로그에서 가장 가까운 소재를 제안하고 사용자가 확인한다. 맞는 소재가 없으면 '목록에 없음' 경로(일반 경로 또는 문의 안내)로 간다. 법적 지위는 LLM이 정하지 않는다.
5. **소재와 무관한 확인은 줄이되 없애지 않는다.** 폐기물 여부·다른 법 적용·사업장폐기물 여부는 관문 묶음 질문과 사업장 정보로 처리한다(이미 구현).

## 3. 목표 문진 흐름

```
① 소재(카탈로그, 묶음 → 소재)            예: 플라스틱 → PP
② 이 물질을 어떻게 하나요(폐기물 여부)    예: 내보낸다
③ 해당하는 것이 있으면(관문 묶음)         예: 해당 없음
   [사업장 정보: 처음 한 번만]
④ 상태 — 소재가 상태를 정하지 않을 때만    예: 고체
⑤ 오염 체크리스트(그 소재에 걸리는 항목만)  예: 모두 아니오
⑥ 같은 소재 안 번호 가르기(필요한 소재만)   예: (PP는 없음)
⑦ 시험이 필요한 소재면 성적서 묶음
→ 결과: 분류번호 + 지정 여부 + 재활용 유형 + 판정 기록
```

PP 고체 예시는 ①~⑤, 5화면에서 51-03-01이 정해진다(두 번째 폐기물부터 사업장 질문 생략).

## 5. 단계별 계획

### 1단계. 출력 계약: 판정 기록 형식

이후 단계는 화면 응답이 아니라 판정 기록만 읽는다.

- 항목별 상태(DETERMINED / PROVISIONAL / OPEN / NOT_APPLICABLE)와 값: 폐기물 여부, 법 적용, 사업장폐기물, 지정 여부, 분류번호(`how: AUTO`), 위험 표시(PCB·유해화학물질·기름·상태), 재활용 유형(사전 분석 여부 포함), 신고 대상 여부
- 근거(조문·판), 쓰인 사실과 그 출처(USER / DOCUMENT / TEST), 남은 확인 사항(무엇이 왜 필요한지)
- `material_id`, 기준일, 규칙 버전, 엔진 버전, 같은 입력이면 같은 고유값(`record_hash`)
- 이후 단계 규칙: "DETERMINED이고 신뢰 기준 이상인 항목만 자동으로 쓴다"

완료 기준: JSON 스키마와 스키마 검사 테스트, 해시 재현 테스트.

### 2단계. 소재 카탈로그와 소재 우선 문진

- `rules/materials.yaml` 작성(4절의 약 30종부터).
- 첫 질문을 소재로 바꾸고, 소재가 정하는 사실은 미리 채운다. 엔진은 사실을 받는 순서와 관계없이 같은 결론을 내므로 판정 로직은 바뀌지 않는다.
- 같은 소재 안 번호 가르기 질문 추가(목재의 사용 물질, 분진·오니·소각재의 발생 공정·시설 등). 법령 명칭에 적힌 구분 기준만 질문으로 만든다.
- 기존 '폐기물 종류' 32개는 카탈로그 묶음 아래로 들어가고, '위 목록에 없음'은 LLM 소재 제안 + 확인으로 대체한다.
- SCRAP 문진 화면: 디자인의 첫 질문(주된 물질) 자리에 카탈로그 묶음 → 소재를 넣는다.

완료 기준: 카탈로그의 모든 소재에서 사용자가 법령 명칭 목록을 보지 않고 번호가 정해짐(용출시험 등 시험이 필요한 경우는 시험 안내로 멈춤). 대표 소재의 화면 수 측정.

### 3단계. 소재별 판정표 생성기

- `tools/material_tables.py`: 소재마다 걸리는 질문을 엔진에서 뽑아 모든 답 조합을 돌리고, "답 → 지정 여부·분류번호·재활용 유형·상태" 표를 만든다(숫자 질문은 기준값 경계 위·아래).
- 출력: 검토용 표(사람이 읽는 md/csv)와 기대값 파일(테스트).
- 테스트: 생성된 표와 기대값 파일이 다르면 실패 → 규칙을 바꾸면 어느 소재의 어느 칸이 바뀌는지 바로 보인다.

완료 기준: 카탈로그 전 소재의 표 생성, 회귀 테스트로 연결.

### 4단계. 알려진 빈틈 일괄 수정

| 빈틈 | 방향 |
|---|---|
| 순환자원 제23조(지정·고시) 미반영 | 인정서 외에 '고시 품목이며 고시한 용도·방법을 지키는가' 경로 |
| 순환자원 인정 유효성 미확인 | 재인정 기한(제21조③)·조건(④) 확인, 결과에 유효기간 |
| 소각시설 분진 | 소재 카탈로그에서 소각재(비산재)와 집진 분진을 나눠 해결 |
| 답 수정 시 재확인 규칙이 코드에 고정 | 사실 간 의존 관계를 facts.yaml로 |

### 5단계. 신뢰 수준과 증빙

- 항목마다 `trust` = 그 결론에 쓰인 것 중 가장 약한 요소(규칙 검토 여부, 법령/해설, 사실 출처 TEST > DOCUMENT > USER). 확률은 쓰지 않는다.
- 답에 증빙(문서 종류·번호·날짜·기관)을 붙일 수 있게 하고, 분석값 유효기간은 정책값으로 기록.

### 6단계. 규칙 검토와 평가 (계속 진행)

- 검토 단위: **공통 규칙**(관문·사업장·오염 기준 등, 소재와 무관) + **소재별 판정표**(3단계 출력). 소재별 표는 한 장씩 검토할 수 있다.
- 검토자 2인 확인 → REVIEWED, 검토 기록을 파일에 남김.
- 독립 사례 평가: 오판율, 과신율(확정했는데 틀림), 판정 가능 비율.
- 규칙 개정 시 저장된 판정 기록을 다시 계산해 결론이 바뀐 목록을 낸다.
